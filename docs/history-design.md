# 히스토리 설계

## 저장소

`HistoryRepository`가 로드, 검색, 필터, 중복 확인, 추가·갱신을 정의합니다. 현재 `BrowserHistoryRepository`가 `localStorage`를 사용하며 향후 데이터베이스 구현으로 교체할 수 있습니다.

## 신원 매칭

채널 ID, 확인된 정규 채널 URL, 확인된 핸들, 수동 확인 별칭, 정규화된 정확한 채널명 순서로 비교합니다. 검색 URL, 영상 URL, 키워드·카테고리 페이지는 신원으로 사용하지 않습니다. 퍼지 매칭은 하지 않습니다.

## 저장 정책

추천은 `recommended`, 보류는 `candidate`, 제외는 `excluded` 히스토리 상태로 저장합니다. 동일 신원은 새 행을 만들지 않고 기존 행을 갱신하며, 더 강한 채널 ID·URL·핸들 근거가 나중에 확인되면 기존 미확인 신원을 보강합니다. 수동 교정과 사유 코드, 한국어 설명, 근거 요약, 실행 ID, 생성·갱신 시각을 함께 기록합니다.

호환 JSON은 `channel_name`, `url`, `status`만 내보내며 저장소의 원본 역할을 하지 않습니다.
