## 현재 제한사항

- 히스토리는 서버의 로컬 SQLite 파일에 저장되며 여러 서버 인스턴스 사이에 자동 복제되지 않습니다.
- 목 근거는 실제 크리에이터 증거가 아닙니다.
- 규칙 엔진은 공급된 입력 데이터만 평가합니다.
- 최근 조회 평가기는 공급된 조회수 배열이 이미 비교 가능한 동일 형식 표본이라고 가정하며, 영상별 Shorts·롱폼 형식을 자동 분할하지 않습니다.
- 기존 2단계 목 실행은 회귀 하네스로 남아 있으며, H4 자동 실행은 과거·동일 실행 중복을 새 판정으로 표시하지 않고 조용히 건너뜁니다.
- 확정 판정과 히스토리는 SQLite에 지속되지만 현재 실행 결과 묶음은 서버 프로세스 메모리에만 유지되어 서버 재시작 후 상세 화면을 다시 열 수 없습니다.
- 라이브 자동 실행은 공식 YouTube Data API v3 키와 사용 가능한 일일 할당량이 필요합니다. 모든 자동 테스트는 실제 키나 네트워크 없이 허구 목 공급자만 사용합니다.
- H5.1은 공개적으로 보이는 값만 수집합니다. 게이트된 YouTube 이메일 버튼, 로그인·CAPTCHA·쿠키·프록시·지문 회피·URL 추측·제3자 주장·비공개 정보는 사용하지 않습니다.
- 한국어 활동 상태는 언어·활동 신호일 뿐 시청자 지역 검증이 아닙니다. 승인된 일차 출처가 직접 제공하기 전까지 시청자 지역은 미확인입니다.
- YouTube Data API는 Shorts 노출 여부를 직접 제공하지 않으므로 H3는 제공된 지속시간으로 Shorts 길이·롱폼 길이 표본만 파생합니다.
- 공식 API의 검색 연속 페이지 토큰과 쿼리 진행 상태는 SQLite에 저장되며, 토큰이 거부되면 해당 후보 실패를 격리하고 다른 쿼리로 회전합니다.
- 학습 문구는 추천된 공개 메타데이터의 승인된 분류체계 앵커를 포함하는 짧은 문구만 사용하며, 최소 표본 전에는 탐색 상태입니다. AI 추론이나 개인 식별자 학습은 하지 않습니다.
- H6 예약기는 장기 실행 Node.js 프로세스와 같은 SQLite 파일을 공유하는 단일 서버 배포를 전제로 합니다. 여러 서버·서버리스 예약, 외부 분산 잠금과 고가용성은 지원하지 않습니다.
- 운영 중지는 새 수동·예약 실행의 시작을 막으며 이미 잠금을 획득해 진행 중인 실행을 강제 중단하지 않습니다.
- H7은 배포 요구와 책임만 승인했습니다. 실제 호스트, 프로세스 관리자, 네트워크·백업 제품과 배포 자동화는 선택하거나 구현하지 않았습니다.

H4.2는 자동 실행의 수량 의미를 최초 후보 수에서 신규 추천 목표 수로 바로잡았습니다. H4.3은 추천 목표만으로 시작하는 다중 검색어·연속 페이지 자동 발견, SQLite 발견 상태와 적응형 우선순위를 추가했습니다.
