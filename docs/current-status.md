# 현재 구현 상태

마지막 확인: 2026-08-02

## 운영 가능한 기능

- Next.js App Router 기반 스카우트 실행, 실행 기록, 결과 상세, 히스토리, 설정, 추천 진단 화면
- 공식 YouTube Data API v3 전용 채널·최근 영상 혼합 발견
- 안정적 채널 ID 중심 신원 정규화와 SQLite 중복 선검사
- `recommended`, `hold`, `excluded` 세 판정과 100점 마케팅 적합도
- 카테고리 25, 한국 시장 20, 활동성 20, 도달력 20, 진정성 10, 연락 가능성 5의 설정 가능한 배점
- 기본 추천 70점, 보류 50점과 개인 이메일 `contact_ready` 조건
- 조직 이메일, 회사·브랜드·공식·재업로드·무효 채널의 영구 하드 제외
- 활동성·영상 수·조회수·바이럴 편중·구독자 범위·카테고리 불확실성의 점수화와 동적 재검증
- 평균·절사 평균·중앙값과 조회수/구독자 효율 계산
- 결과·히스토리의 점수 구성요소, 연락 준비, 규칙 버전, 적용 설정, 재검증 시각 저장
- 동적 제외 기본 45일, 보류 기본 21일 TTL과 규칙 버전 변경 재검증
- 저장된 실행 근거를 현재 규칙으로 재평가하는 기능
- 수동 추천·보류·제외, 변경 이유·메모와 감사 이력, 자동 재평가보다 높은 우선순위
- 마케터 승인, 연락, 회신, 미팅, 계약, 콘텐츠·캠페인 성과 이벤트 저장
- 카테고리·검색어·규칙 버전별 추천 및 후속 성과 퍼널 진단

## 자동 발견과 실행

- 기본 추천 목표 5명
- 19명 이하 목표는 기본 60초 동기 실행
- 20명 이상 목표는 202 응답 뒤 기본 15분 백그라운드 실행과 상태 polling
- 채널 검색과 `publishedAfter` 최근 영상 검색을 번갈아 사용
- 영상 검색 결과의 `channelId` 추출과 실행 내 중복 제거
- 검색어당 최대 10명 평가 후 다음 검색어로 순환
- 20명 평가 뒤 추천 0명이면 중간·넓은 검색 범위로 확장
- 부분 처리 통계도 검색어 품질에 즉시 반영
- 추천과 안전한 고득점 보류 후보에서만 카테고리 기반 학습 문구 추출
- 카테고리 불일치·중복·실패가 많은 검색어 감점과 냉각
- 실행 설정, 규칙 버전, 단계별 퍼널, 검색어 순서와 검색 전략 저장
- 후보·페이지·시간·공급자 실패 안전 상한과 부분 결과 보존

## 데이터와 운영

- `.data/creator-history.sqlite`를 히스토리와 실행 결과의 서버 원본으로 사용
- SQLite v1~v8 순차 마이그레이션
- v6 적합도·설정·재검증, v7 수동 판정 감사, v8 마케팅 후속 성과
- 신원 키 고유 제약과 즉시 쓰기 트랜잭션 기반 중복 방지
- 자동 실행 상세 결과의 서버 재시작 후 복구
- UTC 저장과 사용자 화면 `Asia/Seoul` 표시
- 예약·잠금·복구·상관관계 이벤트와 운영 중지 백엔드
- 내부 단일 호스트 Node.js 22 LTS, 영속 로컬 SQLite 운영 경계
- 24시간 RPO, 4시간 RTO, 30일 백업 보존과 분기별 복원 점검 기준
- API 키는 커밋되지 않는 `.env.local`에만 저장하며 로그·문서·테스트 출력에서 제외

## 46명 실제 재평가

동일한 기존 저장 근거를 새 규칙으로 재생했으며 추가 YouTube API 할당량은 사용하지 않았습니다.

| 지표 | 이전 | 현재 |
| --- | ---: | ---: |
| 평가 | 46 | 46 |
| 추천 | 0 | 7 |
| 보류 | 6 | 30 |
| 제외 | 40 | 9 |

- 정적 적격 37명
- 70점 이상 19명
- 개인 연락 준비 16명
- 70점 이상이면서 개인 연락 준비 10명 중 필수 근거가 확인된 7명 추천
- 조직 이메일 후보 2명은 모두 제외 유지
- 점수 분포: 0~49점 10명, 50~69점 17명, 70~84점 14명, 85~100점 5명
- 참고 목표 수를 맞추기 위한 후보별 예외나 푸드 표본 전용 하드코딩 없음

## 검증 기준선

- ESLint 경고·오류 없음
- strict TypeScript 검사 통과
- Vitest 32개 파일, 260개 테스트 통과
- Playwright Chromium 13개 사용자 흐름 통과
- 공식 공급자 테스트는 실제 키나 네트워크 없이 허구 응답만 사용
- 로컬 서버에서 재평가 결과, 히스토리, 설정, 새 실행, 추천 진단, 실행 상태 API HTTP 200 확인
- 프로덕션 빌드와 Playwright 결과는 [`verification.md`](verification.md)의 최종 명령으로 재현

## 현재 제한사항

- 공식 YouTube API 일일 할당량과 특히 `search.list` 비용에 영향을 받습니다.
- Shorts와 롱폼 지속시간 표본은 분리하지만 적합도 조회 기준은 아직 형식별로 분리하지 않습니다.
- 공개 정보만 사용하므로 시청자 지역, 비공개 연락처와 게이트된 이메일은 확인하지 않습니다.
- 후속 성과는 분석용으로 저장하며 규칙이나 가중치를 자동 변경하지 않습니다.
- SQLite 단일 호스트 배포를 전제로 하며 다중 서버·분산 잠금·고가용성은 지원하지 않습니다.
- 인증, 사용자별 권한, 외부 운영 데이터베이스, 실제 배포 자동화는 구현하지 않았습니다.
- 운영 중지는 새 실행만 막고 이미 시작된 실행을 강제 중단하지 않습니다.

제품 규칙은 [`product-rules.md`](product-rules.md), 이번 결정과 백테스트는 [`decisions/012-marketing-fit-scoring-and-learning-loop.md`](decisions/012-marketing-fit-scoring-and-learning-loop.md)를 기준으로 합니다.
