## 현재 제한사항

- 히스토리는 서버의 로컬 SQLite 파일에 저장되며 여러 서버 인스턴스 사이에 자동 복제되지 않습니다.
- 목 근거는 실제 크리에이터 증거가 아닙니다.
- 서버 측 자동 스카우팅을 실행할 수 없습니다.
- 규칙 엔진은 공급된 입력 데이터만 평가합니다.
- 최근 조회 평가기는 공급된 조회수 배열이 이미 비교 가능한 동일 형식 표본이라고 가정하며, 영상별 Shorts·롱폼 형식을 자동 분할하지 않습니다.
- 현재 목 실행은 과거 히스토리 일치를 엔진의 방어적 `excluded` 결과로 표시합니다. 실제 자동 파이프라인은 이를 근거 수집 전에 조용히 건너뛰도록 H3·H4에서 분리합니다.
- H3 공급자는 UI나 목 실행에 연결되지 않았으며 배치 실행 통계, 판정 호출과 자동 저장 오케스트레이션은 H4 범위입니다.
- YouTube Data API는 Shorts 노출 여부를 직접 제공하지 않으므로 H3는 제공된 지속시간으로 Shorts 길이·롱폼 길이 표본만 파생합니다.

H3는 YouTube 공급자 계약, 실제 읽기 전용 어댑터, 안정적 신원 정규화, 원본·정규화 근거 분리, SQLite 사전 확인과 구조화 오류를 구현해 완료했습니다. 자동 테스트는 실제 키나 네트워크 없이 허구 픽스처만 사용합니다. 현재 안전 기준선과 명령은 [`verification.md`](verification.md)에 기록합니다. 다음 승인 단계는 [`next-task.md`](next-task.md)의 H4 자동 스카우팅 실행 파이프라인입니다.
