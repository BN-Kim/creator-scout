# 010 — H7 운영 배포 경계

## 상태

승인됨 — 2026-07-22

## 결정

현재 프로젝트의 승인된 운영 대상은 **내부 네트워크에 배치된 단일 장기 실행 Node.js 22 LTS 애플리케이션 프로세스와 해당 호스트의 영속 로컬 파일시스템**입니다. 특정 클라우드, 호스팅 벤더, 운영체제 또는 프로세스 관리 제품은 선택하지 않습니다. 다음 조건을 모두 충족하지 못하는 환경에는 현재 애플리케이션을 배포하지 않습니다.

- 프로세스가 계속 실행되며 호스트 재시작과 비정상 종료 뒤 다시 시작될 수 있습니다.
- 인스턴스 수는 정확히 1개입니다.
- `HISTORY_DATABASE_PATH`는 릴리스 디렉터리 밖의 쓰기 가능한 영속 로컬 경로를 가리킵니다.
- SQLite 주 파일과 `-wal`, `-shm` 동반 파일이 같은 로컬 파일시스템에 있습니다.
- 애플리케이션 전체와 `/operations`는 공개 인터넷에 직접 노출되지 않습니다.
- 환경 변수와 백업은 애플리케이션 소스·Git·일반 로그 밖에서 관리됩니다.

서버리스 함수, 일시적 파일시스템, 네트워크 공유 파일시스템, 여러 애플리케이션 인스턴스와 무중단 수평 확장은 현재 승인 대상이 아닙니다. H6 예약 확인기는 유일한 애플리케이션 프로세스가 담당하며 외부 예약기, 큐 또는 분산 잠금을 추가하지 않습니다.

## 데이터 보존과 복구 목표

- 운영 SQLite 파일은 최소 24시간마다 한 번 백업합니다.
- 모든 코드 배포와 스키마 마이그레이션 전에도 별도 백업을 만듭니다.
- 복구 시점 목표(RPO)는 최대 24시간입니다.
- 복구 시간 목표(RTO)는 장애 확인 뒤 최대 4시간입니다.
- 일별 백업은 30일 동안 보존합니다.
- 백업은 운영 호스트와 장애 영역이 분리된 운영자 관리 저장소에 암호화해 보관합니다. 특정 제품은 이 결정에서 선택하지 않습니다.
- 분기마다 최소 한 번 비운영 경로에서 복원 점검을 수행하고 날짜, 백업 식별자, 무결성 결과와 소요 시간을 운영 기록에 남깁니다.

SQLite는 WAL 모드이므로 실행 중인 주 파일 하나만 복사하지 않습니다. 승인된 현재 절차는 운영을 중지하고 실행 중 작업이 없는지 확인한 뒤 Node.js 프로세스를 완전히 종료하고, `HISTORY_DATABASE_PATH`의 주 파일과 존재하는 `-wal`, `-shm` 파일을 한 세트로 복사하는 오프라인 백업입니다. 복원도 프로세스를 중지한 상태에서 같은 세트를 동일 경로로 되돌립니다. 온라인 백업 도구나 자동 백업 구현은 별도 승인이 필요한 후속 작업입니다.

## 접근 제어와 비밀 관리

현재 애플리케이션에는 인증과 사용자별 권한이 없습니다. 따라서 배포 운영자는 사설망, VPN 또는 동등한 상위 네트워크 경계에서 승인된 내부 운영자만 애플리케이션에 접근하도록 제한하고 전송 구간 암호화를 담당합니다. 이 경계를 제공할 수 없으면 배포하지 않습니다. 애플리케이션 인증 구현은 H7 범위가 아닙니다.

배포 운영자는 다음 책임을 가집니다.

- 호스트, 영속 디스크, 단일 프로세스 수명주기와 네트워크 접근 제한
- `HISTORY_DATABASE_PATH`, YouTube 공급자 설정과 필요한 비밀의 환경 변수 주입
- 환경 파일의 OS 접근 권한, 비밀 교체와 유출 대응
- 백업 생성·암호화·보존·복원 점검과 RPO/RTO 기록
- 배포 전 `npm run verify`와 배포 후 주요 내부 화면 확인

제품 운영자는 `/operations`에서 예약, 운영 중지·재개와 실행 오류를 확인하고, 백업 또는 배포 작업 전 새 실행을 중지하며 진행 중 실행이 끝났는지 확인합니다. 애플리케이션은 마이그레이션, 히스토리 멱등성, SQLite 잠금과 비밀값 비노출 구조화 로그의 책임만 가집니다.

## 배포·복원 점검 기준

배포 전에는 운영을 중지하고 실행 중 작업이 0인지 확인한 뒤 오프라인 백업을 생성합니다. 배포 후에는 동일한 영속 경로와 환경 설정으로 단일 프로세스를 시작하고 다음을 확인합니다.

- `/`, `/history`, `/operations`가 내부 경계에서 정상 응답합니다.
- `schema_migrations`에 현재 저장소가 요구하는 버전이 모두 존재합니다.
- 기존 히스토리와 예약 작업을 조회할 수 있습니다.
- 운영 중지 상태를 의도대로 유지하거나 명시적으로 재개합니다.
- 새 오류 로그에 비밀값이나 공급자 원문이 포함되지 않습니다.

복원 시에는 프로세스를 중지하고 손상 의심 파일 세트를 별도 보존한 뒤 검증된 백업 세트를 원래 경로로 복사합니다. 백업과 호환되는 애플리케이션 커밋으로 시작하고 위 점검을 반복한 뒤에만 운영을 재개합니다. 빈 데이터베이스 생성이나 일부 테이블 삭제를 복구 방법으로 사용하지 않습니다.

## 결과와 후속 경계

H6의 단일 공유 SQLite와 장기 실행 Node.js 전제는 위 운영 대상에서 유지 가능합니다. 다중 인스턴스, 서버리스, 외부 데이터베이스·큐, 애플리케이션 인증 또는 온라인 백업이 필요해지면 이 결정을 재검토해야 합니다.

H0~H7 계획은 이 결정으로 완료됩니다. 후속 구현은 승인된 활성 작업이 아닙니다. 실제 호스트 세부사항이 별도로 승인될 경우 첫 구현 후보는 **단일 호스트 배포 사전 점검과 오프라인 백업 검증 자동화**로 제한하며, 외부 데이터베이스·인증·공급자·판정 규칙을 포함하지 않습니다.
