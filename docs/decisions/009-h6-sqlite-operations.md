# 009 — H6 운영 상태와 잠금에 SQLite 사용

## 상태

승인됨 — 2026-07-22

## 결정

H6 예약, 운영 중지 상태, 실행 기록, 상관관계 이벤트와 실행 잠금은 기존 히스토리 파일의 버전 3 SQLite 스키마에 저장합니다. 장기 실행 Next.js Node.js 프로세스가 `instrumentation.ts`에서 예약 확인기를 한 번 시작합니다. 수동 실행과 예약 실행은 모두 같은 `OperationCoordinator`를 지나며, 기존 H4 파이프라인을 호출하기 전에 조건부 SQLite 잠금을 획득합니다.

재시도 횟수, 재시도 지연, 실행 시작 간격, 잠금 유효시간과 예약 확인 간격은 유한한 환경 설정 범위로 제한합니다. 만료된 잠금과 소유자 없는 실행은 중단으로 기록하고 기존 히스토리 선검사와 멱등 저장 경계를 그대로 사용해 예약을 다시 실행합니다. 비밀값과 공급자 원문은 운영 이벤트 메타데이터에 저장하지 않습니다.

## 이유

현재 배포 경계는 하나의 로컬 SQLite 파일을 사용하는 내부 애플리케이션입니다. 같은 파일을 공유하는 프로세스 사이의 원자적 조건부 쓰기는 별도 큐나 외부 잠금 서비스 없이 중복 실행을 막고, 예약·실행 상태를 재시작 뒤에도 관찰할 수 있게 합니다. 기존 자동 파이프라인을 복제하지 않고 조정 경계만 추가하므로 판정 규칙과 저장 멱등성을 유지합니다.

## 제한과 재검토 조건

SQLite 잠금은 같은 파일을 공유하지 않는 여러 서버를 조정하지 못합니다. 프로세스 내 예약 확인기는 장기 실행 Node.js 서버를 전제로 하며 서버리스 인스턴스의 지속 실행을 보장하지 않습니다. H7 결정 010은 이 전제를 유지하는 단일 호스트 운영 경계와 백업·복구·접근 제어 목표를 승인했으며, 외부 큐, 운영 데이터베이스, 클라우드 예약기나 인증은 계속 미승인입니다.
