# 007 — 자동 히스토리와 검증 전 중복 건너뛰기

## 상태

승인됨 — 2026-07-22

## 결정

히스토리는 애플리케이션이 자동 생성하고 관리하는 내부 기억입니다. 진정으로 새로운 크리에이터의 모든 확정 판정인 `recommended`, `hold`, `excluded`는 SQLite에 자동 저장합니다.

자동 스카우팅 파이프라인은 발견된 채널을 안정적인 신원으로 정규화한 직후, 비용이 큰 근거 수집과 판정 전에 SQLite 히스토리를 확인합니다. 확정된 과거 신원은 새 평가 결과가 아니므로 조용히 건너뜁니다. 현재 실행 결과에 새 제외로 표시하거나 새 히스토리 레코드를 만들지 않고, 건너뛴 수만 내부 실행 통계나 로그에 기록합니다. 동일 실행 신원 블록리스트도 판정 전에 적용합니다.

중복 건너뛰기는 파이프라인 동작이며 크리에이터 판정이 아닙니다. 판정 모델은 `recommended`, `hold`, `excluded` 세 값만 유지합니다.

사용자에게 과거 히스토리 소스 파일, 파일 업로드, JSON 붙여넣기, 가져오기 실행, 중복 목록 관리 또는 실행 후 히스토리 갱신을 요구하지 않습니다. 3필드 JSON 내보내기는 선택적 호환 출력이며 원본이나 파이프라인 입력이 아닙니다.

## 결과

과거 채널은 반복 검증되거나 재추천되지 않고, 비용이 큰 공급자 호출도 발생하지 않습니다. 현재 실행에는 새로 처리된 크리에이터만 표시됩니다. 현재 목 엔진의 `prior_history_duplicate` 방어 분기는 파이프라인 경계를 우회한 입력을 막기 위해 남지만 실제 자동 실행의 정상 결과로 취급하지 않습니다.
