# 운영 배포 기준선

이 문서는 결정 [`010-h7-production-operating-boundary.md`](decisions/010-h7-production-operating-boundary.md)를 운영자가 점검하기 위한 요약입니다. 배포 스크립트나 특정 호스팅 제품 사용을 승인하는 문서가 아닙니다.

## 승인 토폴로지

| 항목 | 승인 기준 |
| --- | --- |
| 애플리케이션 | Node.js 22 LTS에서 장기 실행되는 Next.js 프로세스 1개 |
| 네트워크 | 공개 인터넷 직접 노출 금지, 승인된 내부 운영자만 접근 |
| 데이터 | `HISTORY_DATABASE_PATH`가 가리키는 영속 로컬 SQLite 파일 세트 |
| 예약 주체 | 동일한 단일 애플리케이션 프로세스의 H6 예약기 |
| 확장 | 수평 확장, 서버리스, 외부 큐·잠금은 미승인 |
| 비밀 | 프로세스 환경으로 주입하고 소스·Git·로그·DB 백업과 분리 |

## 정량 목표

| 항목 | 기준 |
| --- | --- |
| 정기 백업 | 24시간마다 최소 1회 |
| 추가 백업 | 모든 배포·마이그레이션 직전 |
| RPO | 최대 24시간 |
| RTO | 최대 4시간 |
| 보존 | 일별 백업 30일 |
| 복원 훈련 | 분기마다 최소 1회 |

## 배포 전 점검

1. `npm run verify`, `npm run test:e2e`, `git diff --check`가 성공했는지 확인합니다.
2. `/operations`에서 운영을 중지하고 실행 중 작업이 0인지 확인합니다.
3. Node.js 프로세스를 종료합니다.
4. SQLite 주 파일과 존재하는 `-wal`, `-shm` 파일을 같은 백업 세트로 복사합니다.
5. 백업 세트의 파일 목록, 크기, 체크섬, 생성 시각과 대상 애플리케이션 커밋을 기록합니다.
6. 비밀이나 `.env.local`이 백업 세트와 배포 산출물에 포함되지 않았는지 확인합니다.

## 복원 점검

1. 애플리케이션 프로세스를 중지합니다.
2. 현재 SQLite 파일 세트를 삭제하지 않고 장애 조사용 위치에 보존합니다.
3. 검증된 주 파일과 동반 파일 세트를 `HISTORY_DATABASE_PATH`에 복원합니다.
4. 백업과 호환되는 애플리케이션 커밋을 단일 프로세스로 시작합니다.
5. `/history`에서 기존 판정 기록을, `/operations`에서 예약·실행 상태를 확인합니다.
6. 현재 마이그레이션 버전과 오류 로그를 확인합니다.
7. 점검이 끝난 뒤 운영을 명시적으로 재개하고 실제 복구 시간을 기록합니다.

## 중단 조건

다음 중 하나라도 충족하면 배포 또는 운영 재개를 중단합니다.

- 영속 로컬 파일시스템이 보장되지 않습니다.
- 둘 이상의 애플리케이션 인스턴스가 같은 역할로 실행됩니다.
- 애플리케이션이 공개 인터넷에 직접 노출됩니다.
- 백업 세트 또는 비밀 관리 책임자가 지정되지 않았습니다.
- 최근 24시간 이내 백업이나 배포 전 백업을 확인할 수 없습니다.
- 복원 뒤 히스토리, 예약, 마이그레이션 또는 로그 점검이 실패합니다.
