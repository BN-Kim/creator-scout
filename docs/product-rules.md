# 제품 규칙

이 문서는 크리에이터 판정 업무 규칙의 유일한 사람이 읽을 수 있는 기준입니다. 구현은 `src/server/rules`, 계약은 `tests/contracts`가 보호합니다.

## 판정 모델

허용되는 최종 판정은 `recommended`, `hold`, `excluded` 세 값뿐입니다. 점수, 경고, 누락 근거, 중복, 재검증, 수동 수정과 마케팅 성과는 별도 필드나 이벤트로 표현하며 새 판정 상태를 만들지 않습니다.

평가 결과는 현재 `rule_version`, 적용 설정, 100점 `fit_score`, 여섯 점수 구성요소, 연락 준비 여부, 재검증 시각과 판정 출처를 함께 저장합니다. 현재 규칙 버전은 `2026-08-marketing-fit-v1`입니다.

## 점수 모델

기본 배점은 다음과 같고 합계는 항상 100이어야 합니다.

| 구성요소 | 기본 배점 |
| --- | ---: |
| 카테고리 관련성 | 25 |
| 한국 시장 활동 | 20 |
| 활동성·일관성 | 20 |
| 도달력·효율 | 20 |
| 진정성·위험 | 10 |
| 연락 가능성 | 5 |

배점과 임계값은 설정으로 관리합니다. 기본 추천 기준은 70점, 보류 가능한 최소 기준은 50점입니다. 한 개 바이럴 영상 편중은 제외 사유가 아니며 진정성·안정성 점수에서 최대 5점만 감점합니다.

초기 운영 선호값은 최근 90일 안 영상 1개 이상, 60일 안 활동과 영상 2개 이상 우대, 최근 조회수 중앙값 3,000 이상 또는 절사·산술 대표 평균 5,000 이상, 조회수/구독자 비율 10% 이상이면서 중앙값 1,000 이상인 소형 효율 채널 보조 인정, 구독자 1,000~250,000명입니다. 활동·조회·구독자 범위는 점수 신호이며 그 자체로 하드 제외나 숨은 추천 게이트가 아닙니다.

최근 조회는 최신 10개 이내의 확인된 동일 기간 표본으로 중앙값, 산술평균과 충분한 표본일 때 양끝을 제거한 절사평균을 계산합니다. 공급자가 구분한 Shorts 길이·롱폼 길이 표본은 별도로 보존하지만, YouTube가 공식 Shorts 유형을 직접 제공하지 않으므로 현재 판정은 통합 최근 활동 표본을 사용합니다.

## 추천

다음 조건을 모두 충족하면 추천합니다.

- 비협상 하드 제외 사유가 없습니다.
- `fit_score`가 설정된 추천 기준 이상입니다.
- 공개된 개인 소유 이메일이 확인되어 `contact_ready`입니다.
- 카테고리, 활동, 조회 표본 등 판정에 필요한 근거가 미확인 상태가 아니고 소속 근거가 충돌하지 않습니다.

최근 활동 미달, 낮은 조회, 바이럴 편중 또는 구독자 목표 범위 밖이라는 사실만으로 추천을 막지 않습니다. 해당 신호로 점수가 낮아지며 최종 합계가 기준을 넘으면 다른 강점이 약점을 보완할 수 있습니다. 안정적 YouTube 채널 ID가 확인되면 채널명 일치는 별도 추천 게이트가 아닙니다.

## 보류

하드 제외가 없고 다음 중 하나에 해당하면 보류합니다.

- 점수가 50~69점입니다.
- 점수가 70점 이상이지만 개인 연락처가 확인되지 않았습니다.
- 카테고리 또는 필수 검증 근거가 미확인입니다.
- 소속 근거가 서로 충돌합니다.

점수가 높은 보류를 먼저 보여 줍니다. `hold`는 기본 21일 뒤 재검증하며 설정 범위는 14~30일입니다. 검색어의 발견 카테고리는 검증 카테고리가 아니므로 공개 근거가 부족하면 `미분류` 보류를 유지합니다.

## 제외와 하드 게이트

확정 하드 게이트는 점수와 모든 긍정 신호보다 우선합니다. 무효 채널, 영상 없음, 확인된 카테고리 불일치, 해외·연예인·공식·회사·법인·브랜드·재업로드·모음/콘텐츠 팜 채널, 확인된 에이전시·매니지먼트·MCN·레이블 소속과 조직 소유 이메일은 제외입니다.

회사, 브랜드, 에이전시, 매니지먼트, MCN, 레이블 또는 대표 조직의 이메일은 항상 제외입니다. `cj.net`과 명시적으로 설정한 조직 도메인에도 같은 규칙을 적용합니다. 그 밖의 커스텀 도메인은 도메인만으로 조직 소유를 추론하지 않습니다.

`latest_upload_too_old`, `insufficient_recent_video_count`, `recent_views_below_threshold`, `viral_video_distortion`, 구독자 목표 범위와 미확인 카테고리는 하드 제외가 아닙니다. 하드 제외가 없고 점수가 50점 미만이며 근거가 충분한 후보만 동적 저적합 제외가 될 수 있습니다. 동적 제외의 기본 TTL은 45일이고 설정 범위는 30~60일입니다.

## 자동 발견과 실행

사용자 수량은 발견 후보 수가 아니라 신규 추천 목표 수입니다. 기본 동기 목표는 5명입니다. 1~19명 실행은 기본 60초 한도에서 완료된 부분 결과를 반환합니다. 20명 이상은 요청과 분리된 백그라운드 실행으로 처리하며 기본 최대 15분, 검색 25페이지, 후보 1,000명 상한을 적용합니다. 운영 환경 변수로 더 낮거나 허용 범위 안의 다른 상한을 지정할 수 있습니다.

발견은 공식 YouTube Data API v3의 채널 검색과 날짜 필터가 있는 최근 영상 검색을 실행 전체에서 번갈아 사용합니다. 영상 검색 결과에서는 `snippet.channelId`를 추출하고 채널을 중복 제거합니다. 각 API 검색 호출은 한 전략만 사용해 혼합 검색 때문에 호출 비용을 두 배로 만들지 않습니다.

한 검색어에서 후보를 최대 10명 처리한 뒤 다른 검색어로 순환합니다. 추천이 없더라도 20명을 평가하면 `medium`과 `broad` 범위로 확장합니다. 부분 처리 집계는 페이지 완료 전에도 검색어 품질에 반영하되 공급자 페이지 수를 중복 계산하지 않습니다. 검색 결과 URL과 영상 URL은 신원으로 사용하지 않습니다.

검색어 품질은 발견 순서만 바꾸고 판정에는 영향을 주지 않습니다. 안전한 학습 문구는 검증 카테고리가 일치한 추천 또는 추천 점수 이상인 보류의 승인된 공개 메타데이터에서만 추출합니다. 개인 식별자·연락처·URL·금지어는 학습하지 않습니다. 중복, 실패, 카테고리 불일치와 제외 비율이 높은 검색어는 감점·냉각·폐기합니다.

실행 결과에는 적용 설정, 규칙 버전, 단계별 퍼널, 검색어 순서와 채널/최근 영상 전략을 저장합니다.

## 증거 무결성

신원, 채널 URL, 이메일, 구독자, 조회수, 업로드 날짜, 카테고리, 시청자 위치, 소속 또는 검증 근거를 만들어내거나 근거 없이 완성하지 않습니다. 확인하지 않은 값은 `null`, `not_checked` 등으로 유지합니다. 불완전한 공급자 응답을 숫자 0으로 바꾸거나 조회수 누락 영상을 표본에서 조용히 제거하지 않습니다.

공개 연락처는 공식 API의 채널·최근 영상 설명과 채널이 직접 연결한 승인된 공식 사이트에서만 수집합니다. 공개된 완전한 주소의 공백·전각·제로폭·명시적 `(at)/(dot)` 표기만 정규화하며 게이트된 이메일 버튼, 로그인·CAPTCHA·접근 제어를 우회하지 않습니다.

한국어 활동 신호는 시청자 지역 검증과 별개입니다. 승인된 일차 출처가 직접 제공하지 않는 시청자 지역은 미확인으로 유지합니다.

## 히스토리와 재평가

SQLite 히스토리가 유일한 원본입니다. 안정적 채널 ID, 확인된 정규 URL, 핸들, 확인 별칭, 정규화된 정확한 이름 순으로 중복을 확인합니다. 다운로드 JSON은 `channel_name`, `url`, `status` 세 필드만 제공하는 읽기 전용 호환 출력입니다.

추천과 정적 하드 제외는 자동 재평가하지 않습니다. 보류와 동적 저적합 제외는 `recheck_at`이 지났거나 규칙 버전이 바뀌면 다시 검증할 수 있습니다. 저장 실행 재평가는 YouTube API를 호출하지 않고 저장된 근거를 현재 규칙으로 재생하며 원본 실행 ID와 새 결과를 함께 보존합니다.

## 수동 판정과 성과

마케터는 실제 실행 결과의 추천·보류·제외를 이유와 메모를 남기고 변경할 수 있습니다. 수동 판정은 자동 재평가보다 우선하며 변경 전후, 실행, 크리에이터, 이유, 작업자와 시각을 감사 테이블에 남깁니다. 확인된 개인 연락처가 없는 후보는 수동 추천할 수 없고 비협상 하드 제외는 보류나 추천으로 올릴 수 없습니다.

마케터 승인, 연락 시도, 회신, 미팅, 계약, 콘텐츠 발행과 캠페인 콘텐츠 성과를 히스토리에 연결된 이벤트로 저장합니다. 성과 이벤트는 판정을 자동 변경하지 않습니다. 규칙 버전·카테고리·검색어별 퍼널과 실제 후속 결과를 진단 화면에서 비교한 뒤 별도 제품 결정으로 기준을 조정합니다.
