# 제품 규칙

이 문서는 크리에이터 판정 업무 규칙의 유일한 사람이 읽을 수 있는 기준입니다. 구현은 `src/server/rules`, 계약은 `tests/contracts`가 보호합니다.

## 판정 모델

허용되는 판정은 다음 세 값뿐입니다.

- `recommended` — 추천
- `hold` — 보류
- `excluded` — 제외

명시적인 제품 결정 없이는 새로운 크리에이터 판정 상태를 추가하지 않습니다. 사유, 경고, 누락 근거, 중복과 수동 교정은 별도 필드로 표현합니다.

## 추천

추천은 모든 필수 검사를 통과해야 합니다. 확인된 YouTube 크리에이터 신원과 채널 또는 핸들 URL, 영상 존재, 설정된 기간 내 최근 활동, 최소 최근 영상 수, 충분한 최근 조회 성과, 카테고리 일치, 국내 활동 적합성, 확인된 개인 소유로 보이는 공개 이메일이 필요합니다. 확정 제외 조건 또는 무효 수동 교정이 없어야 합니다. 과거 히스토리와 동일 실행 중복은 이 판정 단계에 들어오기 전에 파이프라인에서 차단합니다. 안정적 YouTube 채널 ID가 정확히 확인되면 채널명 일치는 별도 추천 게이트가 아닙니다.

자동 실행에서 사용자가 입력하는 수량은 최초 발견 후보 수가 아니라 새로 추천할 크리에이터 목표 수입니다. 과거·동일 실행 중복, `hold`, `excluded`, 공급자·정규화·저장 실패는 추천 목표에 포함하지 않습니다. `hold`와 `excluded`는 히스토리에 저장한 뒤 탐색을 계속하며, 목표를 채울 수 없으면 안전 상한 또는 소스 소진 사유와 부분 충족 수를 명시합니다.

자동 검색의 최대 실행 시간은 1분입니다. 화면은 실행 중 남은 시간을 초 단위로 표시합니다. 1분에 도달하면 추가 탐색과 미완료 후보 대기를 중단하고, 그 시점까지 판정과 저장이 모두 완료된 결과만 `time_limit_reached` 부분 결과로 반환합니다. 미완료 후보는 판정하거나 히스토리에 기록하지 않으므로 다음 실행에서 다시 시도할 수 있습니다.

자동 발견이 기본이며 사용자는 추천 목표 수만 입력해 실행할 수 있습니다. 검색어는 선택적인 고급 설정입니다. `automatic`은 내부 분류체계 검색어만, `manual_replace`는 사용자가 입력한 유효 검색어만, `manual_extend`는 둘을 함께 사용합니다. 내부 검색어는 외부 AI 없이 결정론적으로 생성하며 이름·채널명·핸들·이메일·URL·ID 또는 금지 대상을 사용하지 않습니다. 검색어 품질과 학습 문구는 발견 순서만 조정하며 크리에이터 판정에는 영향을 주지 않습니다.

## 보류

보류는 잠재적으로 적합하고 확정 제외 조건이 없지만 비치명적인 사실이 하나 이상 확인되지 않았을 때만 허용됩니다. 이메일 미발견, 미확인 또는 소유 유형 불명은 다른 확정 제외 조건이 없다면 보류가 될 수 있습니다.

확인된 조직 소속은 제외하고 서로 충돌하는 소속 근거는 보류합니다. 확인된 소속이 없거나 소속 근거가 미확인이라는 사실만으로는 보류하지 않습니다. 한국어 활동 상태 `likely`는 국내 활동 적합성을 충족할 수 있습니다. 시청자 지역은 별도 개념이며 미확인 상태만으로 보류하지 않습니다. 추천에는 계속 확인된 개인 연락처가 필요합니다.

공개 연락처는 공식 API의 채널 설명과 최근 업로드 영상 설명, 그리고 채널이 직접 연결한 승인된 공식 사이트에서만 수집합니다. 일반 `name@domain.com`, 기호 주변 공백, 전각 `＠/．`, 명시적인 `(at)/(dot)`·`[골뱅이]/[dot]`, HTML 이메일 기호 표기는 공개된 완전한 주소로 정규화할 수 있습니다. 로컬 파트나 전체 도메인이 보이지 않으면 추측하거나 완성하지 않습니다. 게이트된 YouTube “이메일 주소 보기”는 자동화하지 않습니다.

## 제외와 하드 게이트

확정된 하드 게이트는 모든 추천 신호와 보류 조건보다 우선합니다. 회사, 에이전시, 매니지먼트, MCN, 레이블 또는 대표 조직의 이메일은 항상 제외입니다. `cj.net`은 명시적으로 승인된 조직 소유 등록 가능 도메인이므로 주변 문구가 없어도 회사 연락처로 분류합니다. 환경 설정으로 추가한 조직 도메인에도 같은 규칙을 적용합니다. 그 밖의 커스텀 도메인은 도메인만으로 조직 소유를 추론하지 않고 기존 공식 사이트·주변 문맥 검증을 유지합니다. 사용자의 무효 교정도 제외입니다. 그 밖의 하드 게이트와 사유 코드는 `src/config/recommendation-rules.ts`의 `exclusionReasonMappings`와 `src/server/rules/reason-codes.ts`가 소유합니다. 현재 규칙 엔진의 과거·동일 실행 중복 사유는 파이프라인 경계를 우회한 입력을 막는 방어 장치이며, 정상 자동 실행에서 새 제외 결과를 만드는 용도로 사용하지 않습니다.

## 증거 무결성

크리에이터 신원, 채널 URL, 이메일, 구독자 수, 조회수, 업로드 날짜, 카테고리, 시청자 위치, 소속 또는 검증 근거를 만들어내거나 근거 없이 추론하지 않습니다. 확인하지 않은 값은 `null`, `not_checked` 등 명시적인 미확인 상태로 유지합니다. 검색 결과 URL과 영상 URL은 채널 신원을 확립하지 않습니다.

공급자 응답이 사용 불가·비지원·형식 오류이면 확인된 숫자 0으로 바꾸지 않습니다. 확정적으로 파싱된 빈 영상 목록만 최근 영상 수 0으로 판정할 수 있습니다. 핵심 YouTube 근거를 해석하지 못한 후보는 평가·판정·히스토리 저장 없이 실패로 격리해 이후 실행에서 다시 시도할 수 있게 합니다.

채널 설명 수집과 최근 영상 설명 수집은 별도 완료 상태를 보존합니다. 최근 영상 설명 수집이 실패해도 먼저 확인된 채널 설명의 공개 이메일은 유효합니다. 반대로 공개 이메일이 없고 승인된 설명 출처 일부를 확인하지 못했다면 `not_found`가 아니라 `not_checked`로 유지합니다. 동일한 개인 이메일의 출처별 반복이나 서로 다른 복수 개인 이메일은 그 자체로 소유 유형 충돌이 아닙니다.

한국어 활동 근거는 채널 제목·설명, 공개 국가·언어 메타데이터와 최근 공개 영상 최대 20개의 제목·설명에서 결정론적으로 계산합니다. 제목 한글 포함 비율, 한글 문자 비율과 명시적 한국 국가·활동 위치 근거를 별도로 보존하며 최종 상태는 `likely`, `unclear`, `unlikely`뿐입니다. 이 상태는 한국 시청자 지역을 검증하지 않으며, 승인된 일차 출처가 직접 제공하지 않는 한 시청자 지역은 미확인입니다.

## 히스토리

히스토리는 애플리케이션이 자동 생성하고 관리하는 내부 기억입니다. 사용자는 과거 파일을 제공하거나 JSON을 붙여 넣거나 중복 목록을 관리하거나 실행 후 히스토리를 갱신할 필요가 없습니다.

자동 실행은 발견된 채널을 안정적인 신원으로 정규화한 직후, 비용이 큰 근거 수집과 판정 전에 SQLite 히스토리를 확인합니다. 확정된 과거 일치는 새 평가 결과가 아니므로 조용히 건너뛰고 현재 결과에 표시하거나 새 히스토리 레코드를 만들지 않습니다. 건너뛴 수는 내부 실행 통계나 로그에 기록합니다. 동일 실행 신원 블록리스트도 계속 적용합니다. 중복 건너뛰기는 파이프라인 동작이며 별도 판정 상태가 아닙니다.

진정으로 새로운 채널만 근거를 수집하고 `recommended`, `hold`, `excluded` 중 하나로 판정합니다. 모든 확정 판정은 애플리케이션이 SQLite에 자동 저장합니다. 판정 매핑은 고정입니다.

- `recommended` → `recommended`
- `hold` → `candidate`
- `excluded` → `excluded`

SQLite 저장소가 유일한 원본이며 3필드 JSON 다운로드는 선택적 호환 출력일 뿐입니다. 히스토리 소스 파일이나 가져오기 절차는 제품에 필요하지 않습니다.

## 규칙 소유권

| 규칙 종류 | 소유 모듈 |
| --- | --- |
| 하드 게이트와 우선순위 | `src/server/rules/evaluate-creator.ts`, `src/config/recommendation-rules.ts` |
| 활동·조회 임계값 | `src/config/recommendation-rules.ts` |
| 최근 조회 계산 | `src/server/rules/recent-traffic.ts` |
| 증거 필드와 판정 타입 | `src/types/domain.ts` |
| UI 한국어 라벨 | `src/config/labels.ts` |
| 사유 코드와 한국어 설명 | `src/server/rules/reason-codes.ts` |
| 판정-히스토리 호환 매핑 | `src/server/history/history-record.ts` |
| 3필드 JSON 호환 형식 | `src/lib/creators.ts`, `src/types/domain.ts` |

설정 가능한 활동 기간은 7~60일이고 기본값은 56일입니다. 최소 최근 영상은 2개, 기본 최근 조회 표본은 5개, 확장 표본은 최대 10개, 최소 평균 조회는 10,000입니다. 구독자 임계값은 기본적으로 설정하지 않습니다. 기간 내 공개 영상이 기본 표본 5개보다 적더라도 최소 최근 영상 수를 충족하고 그 공개 영상 전체의 조회수가 확인되면, 확인된 전체 영상의 평균으로 조회수 하드 게이트를 평가합니다.

공식 API는 최신 업로드를 최대 50개까지 수집합니다. 최근 영상 수는 검증 시각을 기준으로 `maximumDaysSinceLatestUpload`일 안에 게시된 영상만 셉니다. 최근 평균 조회수는 같은 기간에 포함된 공개 영상 중 최신 `extendedRecentAverageWindow`개(기본 최대 10개)의 조회수 산술평균입니다. 이 두 값은 화면 표시와 판정에 동일하게 사용합니다. 삭제·비공개 영상이나 게시 시각 누락으로 정확한 기간 내 영상 수를 확정할 수 없으면 영상 수는 미확인으로 유지합니다. 다만 남은 공개 영상의 게시 시각과 조회수가 확인되었으면 그 조회수 표본까지 지우지 않으며, 기본 표본 수 이상이면 조회수 하드 게이트를 독립적으로 평가합니다. 조회수가 누락된 공개 영상은 0으로 바꾸거나 표본에서 조용히 제거하지 않고 조회수 근거를 미확인으로 유지합니다.
