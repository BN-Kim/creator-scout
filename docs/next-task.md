# 다음 승인 단계: H4 자동 스카우팅 실행 파이프라인

H0~H3는 완료되었습니다. 다음 단계는 H3 공급자와 기존 결정론적 엔진·SQLite 히스토리를 연결하는 자동 스카우팅 실행 파이프라인이며, 이 문서는 H4만 정의합니다. 별도 구현 지시 전에는 H4를 시작하지 않습니다.

## 목표

설정된 수의 후보를 발견하고 안정적 신원으로 정규화한 뒤, 과거·동일 실행 중복을 비용이 큰 근거 수집 전에 건너뛰고, 진정으로 새로운 채널만 평가·자동 저장·표시하는 멱등 실행을 구현합니다.

## 범위

- 설정 가능한 후보 배치 발견
- 채널 ID 중심 안정적 신원 정규화
- 동일 실행 신원 블록리스트
- SQLite 히스토리 사전 확인
- 과거 신원의 조용한 건너뛰기
- 신규 신원의 채널·최근 영상 근거 수집
- H3 정규화 근거를 기존 `CreatorInput`으로 조합
- 기존 결정론적 규칙 엔진 호출
- `recommended`, `hold`, `excluded` 확정 판정 자동 저장
- 현재 실행에 신규 처리 결과만 표시
- 발견, 중복 건너뜀, 평가, 추천, 보류, 제외, 실패 실행 통계
- 반복 실행과 재시도의 멱등성
- 단계별 구조화 오류와 부분 실패 격리

## 비범위

- 이메일 스크래핑 또는 자동 연락처 수집
- H5 리크루팅 근거 강화
- 예약·백그라운드 실행과 H6 운영 제어
- AI 기반 판단
- 판정 상태, 규칙 또는 임계값 변경
- UI 재설계
- 히스토리 파일 가져오기

## 완료 기준

- 과거 히스토리 신원은 채널·영상 근거 공급자를 호출하지 않는다.
- 동일 실행의 같은 신원은 한 번만 처리된다.
- 신규 신원만 결정론적 엔진에서 정확히 한 번 평가된다.
- 모든 신규 확정 판정이 SQLite에 자동 저장된다.
- 과거·동일 실행 중복은 새 판정, 결과 또는 히스토리 레코드를 만들지 않는다.
- 현재 실행 화면에는 새로 처리한 결과만 표시된다.
- 실행 통계가 발견·건너뜀·평가·추천·보류·제외·실패를 일관되게 집계한다.
- 반복 실행과 안전한 재시도가 추가 평가·결과·히스토리 중복을 만들지 않는다.
- 한 후보의 공급자 실패가 다른 후보 처리를 중단하지 않는다.
- 기존 세 판정 모델, 규칙 엔진, SQLite와 3필드 JSON 계약이 유지된다.

## 필수 테스트

- 단계별 파이프라인 순서와 공급자 계약
- 동일 실행 신원 블록리스트
- 과거 히스토리 사전 건너뛰기와 공급자 미호출
- 신규 신원의 근거 수집·평가·자동 저장
- 세 판정 매핑과 신규 결과 전용 표시
- 실행 통계 전체 항목
- 반복 실행·재시도 멱등성
- 후보별 부분 실패와 구조화 오류
- 저장 실패 시 일관성
- 기존 단위·공급자·저장소·계약·브라우저 회귀 테스트

## 완료 명령

```bash
npm run verify
npm run test:providers
npm run test:e2e
```

H4는 H3 공급자 경계를 소비해야 하며 공급자 원시 응답이나 판정 규칙을 실행 오케스트레이션 안에 복제하지 않습니다.
