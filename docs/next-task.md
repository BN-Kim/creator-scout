# 다음 승인 단계: H2 서버 영속 히스토리

H1 UI 스모크 테스트가 완료되었습니다. 다음 단계는 서버 영속 히스토리이며, 이 문서는 범위만 정의합니다. 별도 구현 지시 전에는 H2를 시작하지 않습니다.

## 목표

현재 브라우저 `localStorage` 원본을 서버 측 영속 저장소로 교체하면서 기존 `HistoryRepository` 계약, 판정 매핑, 중복 방지와 3필드 JSON 호환성을 유지합니다.

## 범위

- 프로젝트 요구에 맞는 데이터베이스 선택과 결정 기록
- 히스토리 스키마 및 마이그레이션
- `HistoryRepository` 서버 구현
- `localStorage`에서 서버 원본으로 전환하는 명시적 절차
- 판정, 사유 코드, 근거 요약, 실행 ID, 생성·수정 시각과 수동 교정 보존
- 동일 신원 중복 방지와 저장소 계약 테스트
- 기존 UI·단위·계약·브라우저 테스트 호환성

## 완료 기준

- 서버 저장소가 히스토리의 단일 원본이다.
- 브라우저나 기기가 달라도 같은 히스토리를 조회한다.
- 추천 전 히스토리 중복 확인과 자동 저장이 유지된다.
- 반복 실행과 동시 요청이 중복 레코드를 만들지 않는다.
- `recommended → recommended`, `hold → candidate`, `excluded → excluded` 매핑이 유지된다.
- 기존 JSON 내보내기 형식이 유지된다.
- 저장소 계약 테스트, `npm run test:e2e`, `npm run verify`가 통과한다.

## 비범위

- 실제 YouTube 또는 검색 연동
- 레거시 히스토리 데이터 가져오기(H3)
- 인증과 권한
- 예약 작업
- UI 재설계
- 판정 규칙, 임계값 또는 새 판정 상태 변경
- H4 이후 데이터 공급자 작업

H2 시작 시 [`task-template.md`](task-template.md)를 사용해 데이터베이스 선택, 마이그레이션 안전성, 롤백과 테스트 전략을 먼저 명시해야 합니다.
