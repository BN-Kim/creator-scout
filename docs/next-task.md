# 다음 승인 단계: H3 레거시 히스토리 마이그레이션

H2 서버 영속 히스토리가 완료되었습니다. 다음 단계는 실제 레거시 히스토리 마이그레이션이며, 이 문서는 범위만 정의합니다. 별도 구현 지시 전에는 H3를 시작하지 않습니다.

## 목표

연결된 레거시 JSON 배열을 손실 없이 분석하고 SQLite 서버 원본으로 반복 실행 가능한 방식으로 가져오며, 불확실하거나 미해결인 신원을 임의로 합치지 않고 감사 가능한 결과를 남깁니다.

## 범위

- 제공된 레거시 JSON 배열의 명시적 파서와 런타임 검증
- 채널·핸들·영상·검색·기타 URL 분류
- 기존 서버 히스토리와의 확정 신원 중복 조정
- 미확인·미해결 레코드 보존 정책과 가져오기 결과 보고서
- 건식 실행과 실제 실행 모드
- 재실행 멱등성과 부분 실패 안전성
- 실제 레거시 픽스처가 제공될 때만 데이터 가져오기
- 마이그레이션·저장소·기존 UI 회귀 테스트

## 완료 기준

- 입력 레코드가 가져오기, 중복, 미해결 또는 오류로 모두 집계된다.
- 검색·영상 URL을 채널 신원으로 사용하지 않는다.
- 불확실 신원을 임의 병합하지 않는다.
- 동일 입력 재실행이 중복 레코드를 만들지 않는다.
- 건식 실행은 데이터베이스를 변경하지 않는다.
- 실제 실행 실패 시 원본과 기존 서버 히스토리를 손상시키지 않는다.
- 감사 가능한 결과 보고서가 생성된다.
- `npm run verify`와 `npm run test:e2e`가 통과한다.

## 비범위

- YouTube 또는 외부 검색 연동
- 인증과 권한
- 예약·백그라운드 작업
- UI 재설계
- 판정 규칙, 임계값 또는 판정 상태 변경
- H4 이후 데이터 공급자 작업

H3는 실제 레거시 입력 파일과 명시적 구현 지시가 제공된 뒤에만 시작합니다. H2의 현재 v2 브라우저 저장소 전환 경로는 H3 레거시 파서를 대신하지 않습니다.
