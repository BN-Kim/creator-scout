# 다음 승인 단계: H3 실제 YouTube 신원 및 근거 공급자

H0~H2는 완료되었습니다. 다음 단계는 실제 YouTube 신원 및 근거 공급자이며, 이 문서는 H3만 정의합니다. 별도 구현 지시 전에는 H3를 시작하지 않습니다.

## 목표

후보 발견과 YouTube 근거 조회를 명시적인 공급자 계약 뒤에 두고, 발견된 채널을 안정적인 신원으로 정규화한 뒤 비용이 큰 근거 수집 전에 SQLite 히스토리를 확인할 수 있게 합니다.

## 범위

- 후보 발견 공급자 인터페이스
- YouTube 채널·최근 영상 근거 공급자 인터페이스
- 안정적인 채널 ID와 핸들 정규화
- 승인된 공급자를 통한 실제 채널·최근 영상 근거 조회
- 공급자 원본 데이터와 애플리케이션 파생 근거 구분
- 공급자가 필요한 메타데이터를 제공할 때 Shorts와 롱폼 표본 구분
- 할당량, 타임아웃, 제한된 재시도와 구조화 오류 처리
- SQLite 히스토리 사전 확인
- 확정된 과거 신원에 대한 근거 공급자 호출 생략
- 자동 테스트용 허구 픽스처와 목 공급자 응답

## 비범위

- 완전 자동 다중 소스 탐색
- 이메일 스크래핑
- 예약·백그라운드 실행
- AI 기반 판단
- 과거 히스토리 파일 가져오기
- H4 자동 실행 파이프라인과 실행 결과 UI 변경
- 판정 상태, 규칙 또는 임계값 변경

## 완료 기준

- 공급자 구현이 애플리케이션 도메인과 분리된 인터페이스를 따른다.
- 채널 ID와 핸들이 안정적인 신원으로 정규화되고 검색·영상 URL은 신원을 확정하지 않는다.
- 원본 응답과 파생 근거의 출처가 구분된다.
- Shorts·롱폼 구분은 공급된 메타데이터가 충분할 때만 수행한다.
- 할당량, 타임아웃, 재시도 가능 오류와 영구 오류가 구조화된다.
- 과거 히스토리 일치는 근거 공급자를 호출하지 않고 조용히 건너뛴다.
- 건너뛰기는 새 판정이나 새 히스토리 레코드를 만들지 않는다.
- 기존 UI, 판정 엔진, SQLite 저장소와 JSON 내보내기 계약이 회귀하지 않는다.

## 필수 테스트

- 후보 발견·YouTube 근거 공급자 계약
- 채널 ID·핸들 정규화와 URL 종류 경계
- 원본·파생 근거 분리
- Shorts·롱폼 표본 구분
- 페이지네이션과 고정 픽스처 재현
- 할당량·타임아웃·재시도·구조화 오류
- 과거 히스토리 사전 확인 시 공급자 미호출
- 기존 단위·계약·브라우저 회귀 테스트

## 완료 명령

```bash
npm run verify
npm run test:e2e
```

H3 자동 테스트는 픽스처와 목 응답을 사용해야 합니다. 외부 연동은 H3의 별도 구현 지시와 승인된 공급자 구성이 있을 때만 연결합니다.
